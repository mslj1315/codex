# Android 本地工作台设计

## 1. 目标与范围

本阶段在现有 Android 门店建档向导之后，交付可点击、可恢复的本地工作台原型。它用于验证餐饮企业客户的日常使用路径：看见今天最重要的经营问题，进入诊断并创建行动任务，或进入 AI 视频工厂推进一条内容制作流程。

本阶段不连接后端、不上传文件、不调用模型、不提交门店档案，也不执行视频渲染。所有内容均为界面内明确标注的本地演示数据；不得把本地操作描述成 AI 已分析、服务端已保存或视频已生成。

## 2. 导航与进入条件

完成并本地预览四步门店建档后，用户可以进入工作台。应用底部提供四个一级位置：

1. 首页：今日经营工作台。
2. 任务：行动任务列表。
3. 消息：本地提醒占位页。
4. 我的：门店档案入口与本地演示说明。

首页顶部保留门店名称、当天日期和数据完整度。数据完整度必须表示为演示状态，不可当作真实报表同步结果。

## 3. 今日经营首页

首页采用“今日经营优先”结构，不将两个产品入口作为首屏的平级主按钮。

1. 显示一张最高优先级问题卡片，使用固定演示内容：`午市套餐核销下降 14%`。
2. 卡片显示数据完整度、简短的建议验证方向，以及两个动作：`查看诊断` 和 `创建行动任务`。
3. 首页只突出这一件最高优先级事项；通过 `查看全部提醒` 查看其他本地提醒。
4. 卡片下方显示 `经营诊断`、`AI 视频工厂` 两个入口，以及待办任务数量。

## 4. 经营诊断页面

经营诊断必须按固定顺序呈现，以避免只给泛泛的 AI 结论：

1. 数据质量：显示本地演示数据范围、完整度和边界。
2. 诊断问题：说明套餐核销下降的现象及待验证因素。
3. 行动建议：给出可执行的门店动作、负责人、截止时间和观察指标。
4. 反思复盘：显示上轮本地示例任务的状态和结果；如不存在历史记录，明确说明尚无复盘数据。
5. 一句话方向：用一句话说明接下来优先优化的方向。

用户可以从行动建议创建一个本地任务。任务默认包含标题、负责人、截止日、衡量指标和“待开始”状态，并立即在任务页和首页待办数量中反映。创建动作只改变应用内存/已保存状态，不得展示提交成功或同步成功。

## 5. AI 视频工厂页面

视频工厂以六阶段流程展示，不引入数字人、AI 生图或高级时间线编辑：

1. 选题：展示经营数据题材、门店灵感和本地热点三个本地演示来源。
2. 文案：选定演示菜品后展示一段可编辑的本地文案。
3. 文案合规：只审核文字，显示“本地规则演示，不构成平台审核结果”。不审核视频内容。
4. 分镜：按镜头给出文案句子、拍摄提示和素材槽位。
5. 素材：显示本地素材上传占位状态，不读取或传输真实文件。
6. 视频库：显示一个本地示例视频条目和处理状态占位；不得显示“已生成”。

每一步都可前进或返回修改，保留已选主题、文案和进度。AI 文案生成、平台规则服务、文件技术检测、自动剪辑、静默渲染与通知均留到服务端与媒体服务阶段。

## 6. 状态与恢复

工作台、任务及视频工厂演示状态使用 Android `SavedStateHandle` 保存。进程重建或配置变化后，当前标签页、已创建任务、选题、文案和视频工厂步骤应恢复。

本地演示状态与未来 API 模型隔离，使用稳定的领域值，不持久化 Android 枚举名称。门店业态继续使用既定接口值，例如 `chinese_dining`。

## 7. 验收标准

1. 用户可从完成的本地建档进入首页，并看到单一最高优先级问题。
2. 用户可从首页进入诊断页，查看五段固定结构，并从行动建议创建本地任务。
3. 创建的任务在任务页和首页待办数量中可见，重建界面后仍保留。
4. 用户可从首页进入视频工厂，完成六阶段演示流并返回修改。
5. 用户在整个流程中看不到任何“已同步”“AI 已分析”“已提交”或“视频已生成”的虚假成功表述。
6. 新增领域和 ViewModel 行为以 JVM 单元测试先行验证；完整单元测试与 `assembleDebug` 必须通过。
