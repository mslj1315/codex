# 餐饮门店运营 AI App 设计

## 1. 产品定位

面向单店餐饮企业客户的移动端运营工作台。第一阶段交付 Android 原生 App，第二阶段在复用同一后端、API 合约和数据模型的前提下交付 iOS App。产品由两个一级入口组成：经营顾问和 AI 视频工厂。两者共享同一份门店档案、经营数据、动态标签、行动任务和内容资产，形成持续的经营闭环，而不是两个独立的 AI 工具。

核心承诺是：帮助店主每周明确一个经营方向，完成不超过三项可衡量的行动；把需要获客、推广或曝光的经营任务转化为可拍、可剪、可发布的短视频。

首批支持中式正餐、快餐/小吃、火锅/烧烤、茶饮/咖啡、烘焙/甜品五类业态。

## 2. 用户与商业模式

主要客户是门店企业客户，由门店主体直接签约。企业管理员可以邀请店长和员工使用同一门店账户。App 只为已获授权的企业成员提供登录、使用和服务状态展示。

销售、合同、年度云服务、API 绑定、视频资源和续费由企业在 App 外完成。App 内不得展示将用户导向微信购买、报价或续费的按钮、链接、二维码或文案。App 内客服仅处理技术支持、问题反馈和服务使用问题。

授权由后台的企业合同和权益记录驱动，包括有效期、门店数、AI 模式、视频额度、存储额度和成员数。若后续推出面向个人店主的 App Store 零售版，数字功能解锁和资源包须通过 IAP 设计，不与企业授权链路混用。

AI 模式分为两种：

- 托管额度：企业购买平台提供的 AI 额度，平台按作业记账并设限额。
- 自备 API：企业在安全服务端绑定自己的模型 API 密钥，平台仅代为调用、计量和限流。密钥加密保存、可解绑和轮换，不进入移动端或日志。

## 3. 用户端信息架构

用户端有五个一级入口：

1. 今日：展示本周一句话方向、数据异常、待完成任务、视频生成状态和关键提醒。
2. 经营顾问：数据导入与确认、周诊断、日异常简报、经营问答、趋势与历史报告。
3. 视频工厂：选题池、文案、文字合规、分镜拍摄、素材上传、生成队列和视频库。
4. 任务：行动建议转化的待办，包含负责人、截止日、目标指标、状态和结果备注。
5. 我的：门店资料、成员、数据授权、API/额度状态、存储、服务状态、技术支持和隐私删除。

首次登录前必须完成门店建档。建档采用四步向导，允许保存草稿，但完成前不可生成正式经营诊断：

1. 门店基础：店名、城市、商圈、业态、开业时间、面积、座位、营业时段。
2. 产品定位：招牌菜、价格带、客单价、目标客群、消费场景和竞争门店。
3. 经营现状：营业额、订单、毛利、主要成本、渠道占比、团购套餐和推广预算。
4. 当前目标：最大问题、30 天目标、可投入资源、抖音账号和内容能力。

门店事实档案与动态经营标签严格分开。事实档案只能由用户修改并保留版本；动态标签由已确认的数据和对话生成，必须标记依据、生成时间、有效期和置信度，不能覆盖事实档案。

## 4. 经营顾问闭环

经营顾问采用“每周完整诊断为主、每日异常提醒为辅”的节奏。周报告固定顺序如下：

1. 数据体检：导入后的字段映射、识别置信度、缺失字段和数据完整度。
2. 上周复盘：检查上周任务是否执行、执行程度、结果和阻碍。首周无历史任务时跳过。
3. 本周诊断：以门店自身历史基线为主，对比营业、订单、客单、毛利、渠道和抖音漏斗变化；按业态题库提出问题树和验证路径。
4. 一句话定调：明确本周唯一优先经营方向，避免输出多个相互冲突的目标。
5. 行动任务：最多三项，每项都有负责人、截止日、操作步骤、目标指标和完成标准。
6. 日常跟进：异常提醒、任务催办、随时问答和结果补录。

复盘必须在新建议之前。复盘结果只能归为四类：已执行且有效、已执行但无效、未执行、数据不足。AI 要根据结果继续放大、修正、拆小或暂停原任务，不能每周无依据地换方向。

报告需要清楚区分事实、与基线的比较、可能原因、结论置信度和待补数据。没有足够数据时，AI 必须说明“数据不足”，并列出最小补数要求；不得把相关性写成因果，也不得就食品安全、税务、法律、用工等专业领域给出确定性结论。

## 5. 数据导入与抖音效果评估

首版采用“截图/报表/表格导入 + AI 结构化 + 用户确认 + 缺项补录”的混合方式。平台自动授权同步作为后续能力，不是首版依赖项。

导入来源包括团购报表、收银或经营报表、抖音本地生活报表、Excel/CSV 和手工输入。每个字段必须记录来源、时间范围、单位、原始文件、识别置信度和确认状态。未确认的数据不能驱动高风险诊断结论。

抖音数据同时追踪自然内容与本地生活团购/付费推广，并按以下漏斗分析：

1. 曝光：播放量、覆盖人数、3 秒留存、完播率。
2. 兴趣：点赞、评论、收藏、分享、主页访问。
3. 到店意向：门店页访问、商品点击、套餐详情、电话或导航。
4. 交易：套餐销量、GMV、成交转化率、退款率、获客成本。
5. 核销与利润：核销率、到店人数、连带消费、毛利和投产比。

视频工厂主要优化前三级内容指标和商品点击；经营顾问以核销后的毛利和投产比判断推广是否产生真实经营价值。无法获得的指标必须显示为缺失，不得由 AI 推测。

## 6. AI 视频工厂

视频工厂的选题来源有四类：

1. 经营数据题材：新品、热销菜、低曝光高复购菜品、套餐目标和经营任务。
2. 门店灵感：顾客赞美、员工故事、真实制作过程、开心或有趣的日常。
3. 合规热点池：由正式数据源与运营后台维护，记录地区、来源、时效、风险等级、适用业态和禁用状态。
4. 参考内容：用户粘贴公开文案或链接，系统只提取主题、结构与节奏，不复制原内容的独特表达。

系统根据经营相关性、时效、可拍性、转化目标和文字合规风险给选题打分。用户选定目标后，系统按平台生成文案，例如抖音短视频口播或小红书笔记；一稿不直接复用到不同平台。

文案在用户确认前经过双层审核：规则词库初筛与 AI 上下文审核。审核范围限于文案，包括平台风险、食品宣称、价格与活动期限、隐私、肖像描述、版权风险和敏感热点。系统不审核用户上传视频的画面内容。

通过文案审核后，AI 将文案拆为逐镜头拍摄卡。每张卡包含原文、时长、镜头目的、景别、机位、具体动作、环境要求、拍摄提示和独立上传位。用户可按镜头上传或重拍。

上传视频只进行程序化技术质检：横竖屏、分辨率、时长、黑屏、亮度、音轨和文件完整性。系统不做视频内容合规判断。上传前用户必须确认拥有素材、出镜人物和音乐的使用授权；视频库默认私有，App 内不建立公开内容社区。后台仍需支持投诉受理、下架、删除和审计记录。

媒体流水线按以下顺序执行：素材技术质检、缺镜头提示、按分镜排序、裁切和头尾清理、字幕排版、模板封面、授权配乐、基础转场、渲染、失败重试、完成推送、视频库预览与导出。首版提供换镜头、改字幕、换封面或配乐后重新生成的轻量修改能力；不提供专业时间线编辑器、数字人口播、全 AI 画面或自动代发到抖音/小红书。

## 7. 系统架构与数据边界

Android App 仅处理交互、登录、表单和受控上传；第二阶段 iOS App 使用同一 API 合约。业务 API 负责账号、企业、门店、任务、报告、权益和用量；AI 编排服务负责题库、模型路由、结构化输出、提示版本、限流和成本账本；媒体任务服务负责存储、质检、模板剪辑、渲染队列和通知；运营后台负责题库、热点、规则、模板、投诉和成本监控。

数据层包括：

- 关系数据库：企业、用户、门店、指标、标签、报告、任务、权益和审计记录。
- 对象存储：原始文件、截图、视频素材、成片和生命周期策略。
- 任务队列：OCR、AI 作业、渲染、通知和可重试任务。
- 密钥管理服务：自备 API 密钥的加密保存、权限、轮换和撤销。

所有业务记录必须绑定企业、门店和创建者，后端以企业和门店为边界进行访问控制。临时上传使用限时凭证；对象存储设置自动清理策略；用户可申请删除门店资料、素材、视频和账号，删除动作需要记录审计结果。

## 8. 失败处理与成本控制

- 报表识别不确定：显示字段与原图位置，要求用户确认。
- AI 返回无效结构：按 schema 验证并有限重试；仍失败时保留草稿和明确错误状态。
- 自备 API 不可用或余额不足：暂停新 AI 作业并告知管理员，不影响历史数据和已生成视频。
- 视频渲染失败：任务按步骤检查点续跑，禁止重复扣减视频额度。
- 通知失败：App 内任务状态是最终可信来源。
- 生成成本：逐作业记录模型、输入/输出 Token、OCR、渲染时长、存储和带宽；按企业、门店、日/月限额报警。

视频流程仅在选题、文案、文字合规、分镜和自然语言修改中调用 AI。素材技术质检、剪辑、字幕排版、转场、渲染和通知采用确定性程序与任务队列，不消耗大模型 Token。这样可避免逐帧视觉分析导致的成本和延迟。

## 9. 运营后台

运营后台包含四个域：

1. 诊断配置：五类业态题库、指标口径、基准策略、建议模板和模型版本。
2. 内容运营：热点池、节日节点、行业内容模板和禁用事件。
3. 安全与服务：文字合规规则、投诉工单、素材下架、账号处置和审计。
4. 成本运维：模型、Token、渲染、存储、队列失败、企业额度和告警。

任何题库、提示词、规则或模板的发布都必须有版本号、发布者、发布时间和回滚能力。

## 10. 上线质量与验收

上线前必须建立并持续运行以下验证：

1. 经营计算测试：客单、毛利、转化、核销和 ROI 的固定样例、边界值与单位换算。
2. AI 评测集：五类业态的黄金案例、错误数据、缺失数据、低置信度和危险建议案例。
3. 文案合规评测：敏感词、上下文歧义、价格、食品宣称、热点风险和参考文案相似性案例。
4. 视频黄金样片：不同机型、比例、编码、缺镜头、重拍、渲染失败恢复和字幕安全区。
5. Android 验收：真机登录、文件上传、后台任务、企业服务状态、账号删除、隐私说明、演示企业账号和服务端可用性。iOS 的真机测试和 App Store 审核演示在第二阶段单独验收。

首版成功不以“能生成报告和视频”定义，而以以下行为结果定义：企业管理员完成建档；门店生成首份诊断；连续四周导入数据；行动任务存在执行记录；用户可独立从选题完成一条视频；单店成本、失败率和任务时延处于事先设定的预算范围内。

## 11. 首版范围与明确排除项

首版交付经营顾问、数据导入确认、周诊断、日提醒、任务闭环、经营问答、视频选题、文案、文案合规、分镜、镜头上传、模板化成片、视频库、企业授权和运营后台。

首版不交付平台自动数据授权同步、自动抓取未经授权的平台内容、视频画面内容审核、数字人、全 AI 画面、专业时间线编辑器、自动发布到外部内容平台、逐份人工经营专家审核或 App 内引导到微信购买/续费。
